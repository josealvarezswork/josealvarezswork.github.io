Why

A clean result can be wrong

My first check on Cuak, a concept project of mine, reported 0 errors. It had skipped every text with more than one color. My own portfolio pages also disagreed with each other. Both problems showed up once something looked for them on purpose.

What for

Order without policing it by hand

  • To see where a project drifted from its own rules, screen by screen or sentence by sentence.
  • To repeat the same check after a change.
  • To keep a record of what was checked, so a claim has something behind it.
How

The agent runs the steps, code checks what it can

  1. 1
    A written procedureA skill file says the steps, their order and when to stop.
  2. 2
    An agent that follows itClaude runs the steps and says what ran and what did not.
  3. 3
    Scripts that checkQuestions with a yes-or-no answer go to code: does this color come from the system, is this quote on the page.
  4. 4
    Me, decidingWhat to fix, what counts as an exception and what gets published.

Not every step is enforced by code. Looking at the screens after a pass, for example, happens only if someone does it.

Folder organisation

A folder should answer one question

These are tools, not apps, so they do not follow an app layout. Files are separated by what they are for and where they run.

  • Configuration apart from behaviour. In Know your design, a new Figma file starts with a new config in projects/.
  • Tests apart from evidence. Tests ask whether the tool works. Evidence keeps what happened on a real file.
  • Before moving a file, check who calls it, what it receives and what it returns.
Not proven yet

What I do not know

  • Whether anyone else can use these flows. No second person has run them.
  • Whether they save time. Nothing was timed.
  • Whether they work beyond my own concept projects and pages.
