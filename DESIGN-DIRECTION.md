# Design Direction — ØDEJ / José Alvarez Portfolio

This is the master creative brief for the whole site. Every page prompt below inherits the Master Visual Direction and the global rule.

**Global rule, applies to every page without exception:**

> Do not make every section look like a scrapbook.

Target ratio per page: **70% clean editorial/UI design — 20% tactile elements (tape, notes, paper) — 10% imperfection/scribbles.** Tactile elements exist to explain the design process, not to decorate the page. If a section reads as "post-it, tape, arrow, paper, scribble" repeated everywhere, the ratio has been violated — pull back toward the 70%.

---

## Master Visual Direction

**Core concept:** "Structured chaos." The site should feel like entering a designer's digital workbench — finished interfaces coexisting with sketches, diagrams, annotations, experiments and design decisions. The underlying structure stays precise, sophisticated and intentional; the expressive layer feels spontaneous, tactile and slightly imperfect.

**Visual language:** Dark editorial design + tactile digital scrapbook + technical design workbench + experimental interface documentation.

**Background:** Deep near-black purple/indigo canvas. Subtle paper grain. Very subtle noise. Faint technical grids and blueprint lines. Soft atmospheric lighting. No pure black.

**Color system:**
- Dominant: deep purple / near-black
- Primary accent: lavender / violet
- Secondary accent: warm amber
- Technical accent: cyan
- Alert accent: red
- Positive / state accent: muted olive green
- Text: warm off-white
- No unrelated colors introduced.

**Typography:** Large, bold, contemporary sans-serif for major headings. Clean neutral sans-serif for body text and UI. Handwritten marker / technical handwriting for annotations. Typography is a visual object, not only information.

**Layout:** Editorial and asymmetric. Avoid repetitive centered layouts, uniform card grids, conventional SaaS composition. Use: overlapping elements, floating labels, large typography, partial overlaps, visual connections, technical diagrams, hand-drawn arrows, circles and underlines, annotations, pinned notes, masking tape, torn paper, translucent technical panels, blueprint fragments, small metadata labels.

**Tactile language:** Paper feels slightly physical. Tape has subtle shadows. Notes can be slightly rotated. Edges can be imperfect. Annotations feel hand-written. But: not childish, not a school notebook, no scrapbook overuse, no visual clutter. Tactile elements explain process — they don't decorate.

**UI language:** Modern, precise, dark interface design. Subtle borders. Soft shadows. Small radius rather than excessive rounding. Controlled glow. Strong hierarchy. High readability.

**Imagery:** 3D renders, mobile UI mockups, technical diagrams, wireframes and design artifacts appear as physical objects inside the composition — screens integrated into the workspace, not dropped into generic device mockups.

**Motion language (where represented):** floating annotations, moving state indicators, progress lines, cursor trails, animated diagrams, transition paths, changing interface states.

**Brand feel:** Experimental, intelligent, human, technical, curious, editorial, slightly mysterious, premium. Final result: "a designer's digital wall of ideas, systems and experiments." Not: generic SaaS, corporate portfolio, Dribbble template, clean Swiss portfolio, generic cyberpunk, excessive glassmorphism, minimal Apple clone, childish scrapbook, Pinterest collage, or random decorative chaos.

## 01 — Home

Hero states the thesis on the left: "Most interfaces show you data. I design the ones that show you what state you're in." On the right, a visual composition of the designer's thinking process: abstract portrait/avatar, state machine diagram, small interface fragments, handwritten annotations, arrows, emotional state notes, technical labels, small UI graphs — reads as a personal design wall.

Case studies (DuoGit, Cuak) are not conventional cards — each is a large artifact pinned onto the workspace, with mobile UI mockups, annotations and small observations around it.

Then Emotional State Architecture: Waiting → Happy → Worried → Broken as a visual state system — cards, characters, arrows, trigger/response relationships.

Close with How I Build: Character Systems / Data Made Readable / Presentation as Action.

Story arc: designer → projects → framework → methodology → collaboration.

## 02 — Wild Frontier (Game UI case study)

The third case study — the one built specifically for the Game UI candidacy. Category: Game UI/UX.

Feels like opening a tactical field notebook documenting the full development of a mobile game interface.

Hero: large title "WILD FRONTIER", subtitle "TACTICAL JUNGLE UI FOR A 4X STRATEGY GAME." Two or three large mobile devices with the game interface, overlapping slightly. Handwritten annotations around them: "Home HUD," "Store," "Information hierarchy," "Fast decision-making," "Resource visibility." Small technical color palette.

01 Design Approach — clarity first, tactical feel, immersive world, built for mobile. Small diagrams and interface fragments.

02 Screen Flow — Home HUD → Map → Build → Units → Store, connected with hand-drawn arrows.

03 Design System — Teko + Inter, buttons, resource bars, status badges, progress bars, cards, icons, tooltips. Presented as a physical technical sheet over the dark canvas.

04 Process — rough wireframes, sketches, iterations, taped onto the workspace like working documents.

05 Key Takeaways — concise handwritten notes combined with precise typography.

The interface itself stays the visual hero throughout.

## 03 — DuoGit

Theme: progression + feedback system. Present as an experimental interface system, not a screen collection.

Hero: large UI mockups (streak, progression, XP, recovery, character state) with handwritten annotations pointing at the mechanics: "Failure becomes part of the loop," "Day 7 recovery rate," "Data is the conversation."

Problem: most gamification punishes absence; DuoGit turns absence into a reason to return. Visualize the loop as an integrated diagram: Absence → State Change → Feedback → Recovery → Progression. Show UI screens beside the diagram.

Tone: game design documentation + interface case study + visual experiment.

## 04 — Cuak

Theme: character-driven fintech UI. Visual language turns slightly warmer while staying inside the dark system. The character is part of the interface architecture, not an illustration added on top.

Hero: three mobile interfaces showing different character states. Annotations: "Character is part of the interface," "State first. Data second," "Feedback becomes visible."

Relationship diagram: User State → Character State → Visual Feedback → User Action. Show the four states (Waiting, Happy, Worried, Broken) and connect them to actual interface behavior.

The page proves the character is a feedback mechanism, not decoration.

## 05 — Emotional State Architecture

The most conceptual page in the portfolio. Large editorial title: "EMOTIONAL STATE ARCHITECTURE." Centerpiece is the state machine itself: Waiting → Happy → Worried → Broken, each state carrying Trigger / State / Behavior / Feedback / Action. Character illustrations represent the states; imperfect hand-drawn arrows connect them; technical notes surround the system.

Hybrid of UX documentation + game design system + technical blueprint + editorial poster. Goal: the viewer understands the designer thinks in systems, not isolated screens.

## 06 — About

Quieter version of the visual system — pull tactile density well below the site-wide 20%, closer to a token amount. Large statement: "I design interfaces that behave, not just interfaces that look good." Introduce José across UI, Game UI, 3D, Motion, Interactive Systems. Large portrait or abstract 3D representation. Small timeline of skills and evolution. Annotations used sparingly.

Feel: personal, human, reflective. Less technical, less visual noise, more personality.

## 07 — Contact

Final collaboration note. Large statement: "Open to contracts and product collaborations." Feels like the last note left on the desk. Include email, LinkedIn, GitHub, availability. One handwritten annotation: "Let's build something meaningful." Visually simple — the feeling of having walked through the workspace and now being invited to work together.
